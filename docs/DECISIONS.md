# Cyberine DevGuard design record

The plugin is a Claude Code port of a personal cross-repo write guard: a PreToolUse hook that stops a session from writing files outside its own repository and the directories the session was allowed. Harness facts cited as `F<n>` were measured on Claude Code 2.1.283 with the probe scripts in `tests/live/`.

## Name

- Name `cyberine-devguard`, display name `Cyberine DevGuard` (plugin and marketplace, skill namespace `/cyberine-devguard:*`, repo config `.claude/cyberine-devguard.json`). Repository `cyberinecore/cc-dev-guard`. The entry script stays `scripts/devguard.mjs` and internal verdict codes keep `devguard-*`; neither is shown in the listing. Measured output quoted in `docs/LIVE-MATRIX.md`, `docs/FAILURE-MODES.md` and `docs/PARITY.md` predates the rename and shows the old `devguard` prefix.
- Collision check, 2026-09-28: npm `devguard` is taken (an MCP dev-diary server, 0.5.0). GitHub `devguard` is an OWASP-listed supply-chain security project (`l3montree-dev/devguard`, 163 stars, with `devguard-action` and a VS Code extension), so the name is likely to hit the directory's "Name matches a known brand" reviewer hold and confuses users in the same security space. Alternatives checked the same day, all with a same-named or near-named project: `repofence` (npm package taken), `scopefence` (a GitHub repo "Repo fences for coding agents"), `writefence` (a GitHub project about agent memory writes), `scopeguard` (a Rust crate with 567 stars), `lanekeeper` (unrelated small repos, npm free), `repo-scope-guard` (npm free, generic words).
- Status: settled by the owner on 2026-09-28. The owner prefix `Cyberine` separates the listing from OWASP DevGuard, which is a different product (supply-chain vulnerability management), while keeping the working name; a reviewer may still read the shared `DevGuard` part as a brand match, and `repotether` stays the fallback if the listing is held.

## Decisions

| ID | Decision | Status |
|---|---|---|
| D1 | Runtime: Node >= 18, zero dependencies, plain ESM modules, exec-form hook `node ${CLAUDE_PLUGIN_ROOT}/scripts/devguard.mjs hook`. Rejected: a function hook (cannot read transcript attachments), committed Go binaries (opaque blobs a directory reviewer holds). node is not bundled with the native installer (F15), so a missing node fails open; the README says so. | PENDING OWNER (recommended) |
| D2 | Modes `ask` (default), `deny-once` (legacy behaviour of the Go hook: deny the first write per session and repo, allow a retry within 10 minutes), `warn` (never blocks, shows a notice), `off`. `ask` holds in every headless mode measured, bypassPermissions and `--allowedTools` included, and inside subagents (F9, F10); in a headless run the reason reaches the model, so the reason is written for both readers. Under bypassPermissions every ask is sent as deny, because Claude Code 2.1.283 lets an ask through there for its safety-check paths (`.claude/`, `.git/`, `.vscode/`, dotfiles; `docs/LIVE-MATRIX.md`). | PENDING OWNER (recommended; measured) |
| D3 | No approval memory in v0.1: PostToolUse carries no approval provenance. Reopened only by backlog task k8xdz. | settled |
| D4 | Two config surfaces. `userConfig` (the user's own, read through the per-option variables Claude Code sets for each `userConfig` field, listed in `scripts/lib/environment.mjs`) may set any option, including extra allowed dirs and hub repos. The repo file `.claude/cyberine-devguard.json` found at or above the session root may only tighten: raise the mode, set `allowIgnored: false`, add `protect` paths. An attempt to widen or to set `off` is ignored with a warning. Any write to a file named `cyberine-devguard.json` under a `.claude` directory asks in every mode but `off`. | settled |
| D5 | Allowances beyond the session repo and allowed dirs, all measured (F16-F21b): the config dir's `projects/*/memory/`, `plans/`, the `autoMemoryDirectory` from the USER settings file only (a repo-controlled project setting could otherwise widen scope; amended by D24), `CLAUDE_COWORK_MEMORY_PATH_OVERRIDE` when set, this plugin's `CLAUDE_PLUGIN_DATA`, the hook input's `scratchpad_dir` when present, and `$CLAUDE_JOB_DIR/tmp/` for background sessions. Non-git targets and gitignored targets (`allowIgnored`, default true) are allowed; a non-git session root allows everything. The Go hook's `~/.claude/memory` hard-code is dropped; users add such paths with the `extraAllowedDirs` option. | settled |
| D6 | Allowed dirs come only from the last environment snapshot in the transcript (F5), read backwards in bounded chunks. Absent, unreadable or unparseable means "unavailable", which never grants: the write asks, and the reason says the list could not be read. The settings-file fallback is rejected (it misses session adds and removals). | settled |
| D7 | Matcher `Write|Edit|NotebookEdit`; MultiEdit no longer exists (F14). Bash and MCP writes are out of scope for v0.1 and the README says so. Hook paths arrive absolute on 2.1.283 (F4); relative paths are still joined to the hook input `cwd` defensively. | settled |
| D8 | Name `cyberine-devguard` / `Cyberine DevGuard`, see above. | settled |
| D9 | Windows is best-effort for v0.1; CI runs the unit tests on Windows, which proves the code paths, not harness behaviour. | settled |
| D10 | An internal error while deciding, unparseable input, or an engine module that fails to load emits `ask` (deny under bypassPermissions) with a readable reason. A missing node, a missing or crashing entry file, non-JSON output or a timeout fails open; a SessionStart hook that also runs `node` makes a missing node visible. Table: `docs/FAILURE-MODES.md`. | settled |
| D11 | The submodule carve-out (a hub repo writing into its own submodules) is opt-in per hub through the user option `hubRepos`, not through a file inside the repo, because D4 forbids a repo from widening its own scope. The Go hook's overlay file `.claude/rules/user-hub-submodules.md` is not read. | settled |
| D12 | Anchor: the session repo is the git common dir of `CLAUDE_PROJECT_DIR` (stays on the launch dir after `cd`, F1; moves into the worktree for `--worktree`, whose common dir is still the main repo's, F2), falling back to the hook input `cwd` when unset or relative. | settled |
| D13 | Decision logging for the parity check is opt-in (`logDecisions`, default false) and writes JSON lines to `CLAUDE_PLUGIN_DATA/decisions.jsonl`: time, session id, tool, target path, verdict. Nothing is ever sent over the network. | settled |
| D14 | Paths are compared after `realpathSync.native` on the existing part, which canonicalizes symlinks and, on case-insensitive volumes, case; the not-yet-existing tail is compared as written, so a variant spelling there is a false ask, never a false pass. | settled |
| D15 | Writes to Claude Code settings files (`.claude/settings.json`, `.claude/settings.local.json`, the config dir's settings files) and to session transcripts always ask, because each can widen scope (additionalDirectories, env, a forged snapshot). devguard option keys set by the session repo's committed `.claude/settings.json` env are applied tighten-only. Project env that hides `node` or preloads code (`PATH`, `NODE_OPTIONS`) is outside what a hook can defend; it is Claude Code's workspace-trust boundary and the README says so (`docs/SECURITY-REVIEW.md` rows 13-16). | settled |
| D16 | Every git call runs with `GIT_*` variables removed and `-c core.fsmonitor=false`, because `git check-ignore` and `git rev-parse` run a target repo's fsmonitor command otherwise. A directory git cannot read but that holds a `.git` entry counts as a repository. | settled |
| D17 | Supersedes D6 as the default grant source, because the Anthropic Software Directory Policy says software "must not query or extract data from Claude's memory, chat history, conversation summaries". Default: allowed dirs come from `permissions.additionalDirectories` in managed, user, project and local settings, from `DirectoryAdded` hook events recorded per session in the plugin data dir, and from the `--add-dir` arguments of the `claude` process (`CLAUDE_PID`; `/proc/<pid>/cmdline`, else `ps`). The transcript snapshot (D6) is opt-in through `read_transcript` and falls back to these sources when unreadable. Cost: without the transcript, a directory removed mid-session stays allowed until the session ends, and `--add-dir` paths with spaces are missed on macOS. Writes into devguard's data dir always ask, because the `/add-dir` records there are a grant. | settled (measured: `docs/LIVE-MATRIX.md` rows add-dir, settings) |
| D18 | Portal Validate findings on a sibling plugin (2026-09-28) are applied here too. "Uses a credential from the user's machine" is text-based and read `.gitignore` lines naming other tools' credential files as the plugin using them, so `.gitignore` names none; those ignores live in each clone's `.git/info/exclude`. "Contains a download-and-run command" is text-based across every file; the only such text left is the CI workflow installing Claude Code to run `claude plugin validate`, which never runs on a user's machine, so a warning there is expected. The plugin ships a square icon because a missing icon is a warning. | settled |
| D19 | Portal Validate on this repo (2026-09-28): `userConfig.mode` drops `options` (a Block: the directory does not accept it yet), and the config code keeps rejecting unknown values. Git children get a fixed list of named environment variables instead of a filtered copy of the whole environment, so no code path copies the environment; the CI workflow no longer runs inline node code. The hook never emits `allow`, as the README now states for the reviewer. | settled |
| D20 | The portal hold "Uses a credential from the user's machine" pairs any file that reads named environment variables (it named `scripts/lib/allowances.mjs`) with any template literal that interpolates an upper-case identifier next to path text, which it reads as an environment-variable reference in a command assembled at run time (the marker directory name, then the repo config file name, each built from the `NAME` constant). Shipped code therefore interpolates only lower-case names; derived file names are literals checked against `NAME` by `tests/package.test.mjs`. `${CLAUDE_PLUGIN_ROOT}` stays in `hooks/hooks.json` and the status skill because the checklist requires hook paths in that form. If the hold still appears, the submission note states that the plugin has no network code and that `tests/live/` probes are developer tools that never run on a user's machine. | settled |
| D21 | The hold's environment side ("reads the installer's environment (printenv / env / export -p / set)") was true in shape: `cli.mjs` passed the whole environment object into every module. Entry points now pass the result of `namedEnv`, a fixed list in `scripts/lib/environment.mjs`; `tests/environment.test.mjs` fails when a module reads a variable not on it. Git keeps its own named list (D19). The send side the scanner names moves between files because it matches any template literal; nothing in the plugin sends data, so a remaining hold is answered in the submission note. | settled |
| D22 | Portal Validate on 0.1.8 (`main` @ 0bdfcf6, 2026-09-28) kept the credential hold with new anchors: the environment side named `docs/DECISIONS.md` (it quoted a variable name with a placeholder key and dollar-brace placeholders), the send side named `scripts/lib/git.mjs` (its one template literal, the `unverified:` marker). The marker is now string concatenation and `tests/package.test.mjs` fails on any backtick in `git.mjs`, the one module that spawns a process; this record describes variable names in words. Neither change alters behaviour. If the hold moves again, the submission note from D21 answers it. | settled |
| D23 | The credential hold is answered, never chased again. A probe branch shipping only the plugin (no `tests/`, `docs/`, `.github/`, `.claude/`, `package.json`) still drew it on 2026-09-28: the environment side moved to `scripts/lib/allowances.mjs` (reading the home and config directory, the plugin's core function) and the send side to the Anthropic schema URL in `.claude-plugin/marketplace.json`. The scanner pairs any environment read with any URL, so no layout clears it; the submission goes in from `main` with the D21 note for the reviewer. | settled |
| D24 | Amends D5: `autoMemoryDirectory` is also accepted from the session repo's `.claude/settings.local.json`, but only while git reports that file ignored (`git check-ignore`, which never reports a tracked file). An ignored local settings file is the user's own file, not something a cloned repository ships, and Claude Code itself reads the key from trusted local settings (F18); a tracked or unignored `settings.local.json` and the project `.claude/settings.json` stay untrusted. The model cannot plant the key silently: D15 asks before every write to a settings file. | settled |
